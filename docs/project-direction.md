# GROIZ：从研究运行平台到自学习智能体框架

> 2026-10-25 方向修订；用户已确认的项目边界。本文变更定位与推进顺序，不宣称新功能交付，不迁移代码、不改命令或 crate 名称。此前“独立治理学习应用”描述现有形态；“第二阶段框架”描述沉淀目标，两者不是两套实现。

## 项目组合与边界

核心工作是两篇独立论文，而不是一个包揽研究、语言、工业系统和桌宠的 GROIZ 大项目。

| 项目 | 主责 | 对 GROIZ 的关系 |
|---|---|---|
| PLC Blueprint Learning（公司论文） | 基于可执行蓝图与反馈学习的 PLC 工程生成；独立 Typst 论文工程 | 可复用经授权的通用机制；基于 coder 自行启动，不等待 GROIZ |
| [Executable Knowledge Learning（个人论文）](../../executable-learning-paper/README.md) | 基于可执行知识与程序演化的智能体持续学习；独立 Typst 论文工程 | 当前最直接消费者；实验可在本仓运行，但论文名称、协议、结果与正文独立维护 |
| [Zio](../zio/docs/project-direction.md) | 通用语言、工具链、宿主机制和通用库 | 核心表达与执行基础，不吸收 GROIZ 的评价、发布或实验业务 |
| GROIZ | 经验、认知程序、学习运行、候选、评价与版本治理 | 现在闭合研究运行路径，第二阶段沉淀可复用框架 |
| [Zioo](../../zioo/README.md) | 独立数字生命与个人助理应用 | 消费框架，不共享宠物 UI、游戏规则或平台生命周期实现 |

公司与个人分开维护数据、规则、实验记录与成果授权。个人任务必须能在没有私有 PLC 样本、IDE 或模板的条件下复现。公司工程内容、凭据与训练产物不进入个人仓库；通用方法的共享仍需遵守来源许可。

## 两阶段演进，而非立刻拆库

### 当前：研究运行平台

优先完成一个真实的“提议 → 执行 → 独立评价 → 晋升/拒绝 → 复用”闭环。保留单机、一个可信协调者和既有 SQLite/制品设施。命令行与 Web 是研究控制面，不是项目的最终产品身份。

### 第二阶段：可复用框架

个人论文验证有效的记忆、抽象和程序演化机制进入稳定合同；未证实机制继续留在实验路径，不作为框架默认能力。框架能被不同任务或应用调用，不以特定 LLM、PLC、桌宠、HTTP 服务或 Web 控制台为前提。

不预先拆出八个包、微服务或多后端抽象。先让现有研究路径可重放，再根据第二个真实消费者明确调用合同。现有控制台可继续作为框架的参考宿主，不另建平行运行时。

## 保留并接通的基础

| 现有资产 | 继续复用 | 不能据此声称 |
|---|---|---|
| `store.zio`、native 存储与制品合同 | 事实、版本、预算、评价引用和发布事务 | 路由返回成功收据就代表评价和发布完成 |
| `runner.zio`、`checkpoint.zio` | 队列、执行状态、暂停/续接和预算关联 | 任意认知程序已能隔离执行，或恢复了完整活动栈 |
| `native/learning/`、`native/app/` | 已有候选、执行、评价、批准和训练实现 | native 测试通过就代表 Zio 部署入口具有同等能力 |
| `workers/torch/` | 许可算子图与参数训练参考后端 | 通用程序演化、本体学习、AGI 或所有设备后端已实现 |
| `examples/self-learning/` | 冻结任务、场景分组、缺失输入和独立标签工装 | 任务 JSON 中的门槛已经在真实 holdout 路径执行 |
| Zio 学习与 Loom 库 | 程序合成、proposer、记忆政策、模型与工具会话 | 受限算术合成就是跨任务学习，或声明式路由就是学得的路由器 |

2026-10-24/25 源码核对发现的优先缺口：

- `api.zio` 的学习选择入口返回收据，批准入口没有调用 `store.zio` 已有的完整评价与发布过程。
- `main.zio` 的 compare/select 展示指标按候选序号计算；这些数字不得进入实验、晋升依据或论文。
- `runner.zio` 对该部署中的 Zio 执行任务有明确拒绝路径；不能把其他 native 入口的执行证据算到这里。
- 实验必须核实实际读取独立测试标签、执行全部门槛和记录重复运行；验证集分数不能替代最终测试集分数。

以上是源码与入口核对，不是本次服务、隔离或完整训练验收。后续实现按真实路径重新验证，不沿用历史 demo 数字充当新结果。

## 框架应稳定的最小模型

先沿用已有记录，字段缺口由真实消费者驱动补充；本表不是新增 API。

| 概念 | 必须可回答的问题 |
|---|---|
| Task / Protocol | 输入、目标、数据切分、允许能力、预算和评价器版本是什么 |
| Experience | 哪次观察、行动和结果，来自哪里，允许谁保存和用于学习 |
| Program / Skill | 真实执行的代码、适用条件、依赖、基础版本是什么 |
| Candidate | 相对哪个父版本改了什么，谁/哪种策略生成，花了多少资源 |
| Run / Checkpoint | 实际执行了哪些步骤，如何终止，续接继承什么预算和状态 |
| Evaluation | 哪个可信评价器对哪个精确制品、数据版本和种子给出什么结果 |
| Publication | 哪个候选基于哪些证据生效，谁批准，预期旧版本是什么，如何回退 |

人格与宠物关系由 Zioo 定义；通用运行状态和经验由 GROIZ 定义。公司 PLC 对象身份与工程正确性由 coder/任务适配器定义。统一表示不意味着不同领域共享一份数据库或相同写权限。

## 学习与安全边界

- 首篇个人论文研究记忆复用、技能抽象和受限程序演化；本体修改、元学习、群体社会学习保留为后续研究，不伪装为现成模块。
- 学习对象是受许可的认知程序、技能与策略。授权、评价器、测试真值、预算账本、隔离和发布控制属于可信边界，候选不得改写。
- 模型输出、执行日志和候选自报指标不是独立质量证据。评价必须绑定制品、数据、运行和协议版本。
- 实验自动选择的版本与用户实际生效版本分开。候选可在预先授权预算内生成/验证；正式升级默认经人工批准，批准不能越过硬门槛。
- 权重、程序、记忆和外部工具状态分别声明恢复范围；缺少隔离/许可/后端时明确失败，不回退到完整宿主权限。
- 测试查询有预算；最终测试不进入候选生成上下文。不能无限试探 holdout 后再宣称未见泛化。

## 推进顺序与完成条件

| 阶段 | 具体动作 | 结束条件 |
|---|---|---|
| G-R1 真实评价 | 选择主执行入口；把演示指标替换为实际 EvaluationRecord；连接已有评价/批准过程 | 同一候选在实际入口完成执行、评价、拒绝/晋升；缺证据、过期版本和不达标候选不能晋升 |
| G-R2 独立验收 | 固定 train/validation/test、种子、任务族与预算；单独运行测试评价 | 能指出测试标签由哪个可信入口读取；训练进程看不到真值；全部冻结指标与失败记录可复算 |
| G-R3 程序学习 | 接通受限 Zio 候选执行与 proposer，复用现有 native/宿主能力 | 生成、拒绝、执行错误、反馈修订和停止均有真实记录；候选不能扩大权限或修改评价器 |
| G-R4 研究对照 | 执行个人论文 B0–B4 与关键消融，不扩张社交/元认知 | 两个任务族报告未见任务、旧任务回归、预算和复杂度；失败与负结果同样保留 |
| G-F 框架沉淀 | 由第二个真实消费者检查经验、程序、运行、评价和授权的最小边界 | 消费者不读写内部数据库、不重建学习引擎；控制台与应用走同一真实过程 |

这些是新方向的验收顺序，不给历史工作包重新标完成，也不在本文维护第二份任务状态台账。下一轮实现应先把 G-R1 拆到现有入口与过程，记录符号影响分析和失败前/修复后证据，不先做全仓库重构。
